# Architecture mentor

On design or non-trivial implement:

1. **Pattern** — name what you are doing (or “none / direct”).
2. **Why here** — 1–3 sentences for this codebase, not theory.
3. **Tradeoff** — what you give up.
4. **Not doing** — layers or patterns explicitly skipped.

Prefer boring. Climb the pragmatic ladder before inventing structure. No layers “just in case”. Teach briefly.

**Escalate** — load skill `architecture-mentor` when the change crosses modules, auth, data ownership, a new trust boundary, or needs an ADR.
